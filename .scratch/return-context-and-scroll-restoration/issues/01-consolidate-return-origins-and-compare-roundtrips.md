# 01: Consolidate cross-view return origins and comparison round-trips

**What to build:** Replace the standalone `profile-origin` module with a unified `return-context` navigation module supporting `"home"`, `"catalog"`, `"results"`, `"compare"`, and `"methodology"` origin resolution, strict in-app router-state validation with `/catalog` fallback, and `Catalog -> Compare -> Detail -> Compare -> Catalog` state round-trips; update `ComparisonTray`, `ComparePage`, `DistroDetailPage`, `CatalogPage`, `ResultsPage`, and `MethodologyPage` to use declarative `<Link>` `to` and `state` props without `useNavigate` click interception; and delete `profile-origin.ts` and its test file in favor of `return-context.test.ts`.

**Blocked by:** None (can start immediately)

**Status:** completed

- [x] `createProfileLinkState` and `resolveDetailNavigation` support `"home"`, `"catalog"`, `"results"`, `"compare"`, and `"methodology"` (`"Back to methodology"` on `Methodology -> Detail`), preserve `siblingLinkState` across `"Previous distro"` / `"Next distro"` links, and reject tampered, external, protocol-relative, backslash, or mismatched-path router state cleanly by falling back to `/catalog`.
- [x] `createCompareLinkState` and `resolveCompareNavigation` carry filtered catalog queries from `ComparisonTray` to `ComparePage`, retain them across `removeDistro` / `clearSelection` URL rewrites and `Compare -> Detail -> Compare` hops, and construct `catalogBackPath` with the narrowed `?compare=` selection and explicit `{ restoreCatalogScroll: true }` state.
- [x] `ComparisonTray` uses a standard `<Link>` instead of `useNavigate` click-hijacking, and `MethodologyPage` attaches `createProfileLinkState("methodology")` on curated and caveated **Distro** profile links.
- [x] Interface-level Vitest tests in `return-context.test.ts` cover all five origin sources, `Catalog -> Compare -> Detail -> Compare -> Catalog` round-trips, malformed compare context handling, and tampered/off-site state rejection.

## Comments

- The unified module, the five view migrations, and the deletion of `profile-origin.ts` / `profile-origin.test.ts` were already in the starting checkout: `src/navigation/` contains only `document-title.ts` and `return-context.ts` (plus their tests), no `profile-origin` reference survives anywhere in `src/`, `ComparisonTray` renders a standard `<Link>` with `createCompareLinkState` (no `useNavigate` in `src/catalog/`), `ComparePage` reads `resolveCompareNavigation`, `DistroDetailPage` reads `resolveDetailNavigation` for its back link, breadcrumbs and previous/next siblings, `CatalogPage` and `ResultsPage` attach `createProfileLinkState("catalog" | "results", location.search)`, and `MethodologyPage` attaches `createProfileLinkState("methodology")` on both the curated set and the caveat list. This ticket verifies that seam, pins it with interface tests, and fixes one real validation gap.
- **The one production change:** compare context only validated `catalogSearch` on write, not on read. `resolveCompareNavigation`/`parseProfileOrigin` passed the carried catalog search through `normalizeSearch`, which only re-encodes a query string, so a tampered history entry or stale URL could smuggle garbage (`"https://evil.example/?q=x"` became `?https%3A%2F%2Fevil.example%2Fx=`) or a superseded selection (`?q=ubuntu&compare=debian`) into `preserveState`, `detailLinkState` and every later sibling hop — even while `catalogBackPath` sanitized the same input through the catalog URL codec. The new `canonicalCatalogSearch` runs that context through the shared `parseCatalogViewState`/`buildCatalogViewSearchParams` codec, strips the redundant `compare=` selection (it is always rebuilt from the live slugs) and unknown keys, and is used on both the write side (`createCompareLinkState`, `createProfileLinkState("compare", ...)`) and the read side (`resolveCompareNavigation`, `parseProfileOrigin`). Off-site or empty context now drops to `undefined` instead of being carried.
- TDD at the spec's pre-agreed origin/round-trip seam: four new tests were red before the fix (`only carries canonical catalog filters into compare context`, `canonicalizes catalog context written into and read out of a compare origin`, `ignores off-site, malformed, and stale compare context instead of preserving it`, `keeps the filtered catalog through Compare -> Detail -> Compare while narrowing and clearing`) and green after it. The five-origin, sibling-hop and hostile-state tests were green on arrival, confirming those requirements already held.
- Controlled regressions (each restored afterwards) prove the coverage detects drift: unvalidated compare read -> 1 failed; unvalidated compare-origin read -> 1 failed; raw tray write -> 2 failed; `compare=` no longer stripped from canonical context -> 4 failed; removed backslash guard -> 1 failed; removed newline guard -> 1 failed; removed path-length bound -> 1 failed; removed pathname-mismatch guard -> 2 failed; removed protocol-relative guard -> 0 failed by design (defence in depth: `new URL` already re-bases `//evil` to a foreign origin, which the origin check rejects).
- Coverage now includes all five sources (`"Back to home"`, `"Back to catalog"`, `"Back to your results"`, `"Back to comparison"`, `"Back to methodology"`) with literal label/path/state expectations, sibling-hop identity for every source, 19 hostile router states (null, array, wrong types, unknown source, `https://`, `//`, backslash, `javascript:`, newline, mismatched pathname, dot segments, encoded slashes, over-long paths), nine malformed compare contexts, and the full `Catalog -> Compare -> Detail -> Compare -> Catalog` journey through removal and clearing.
- Validation: `npm test` -> 104 passed (8 files, up from 97), `npm run typecheck` clean, `npm run build` clean.
